⬆️ Netzwerk-Labor · Spezifikation: Konzept – Netzwerk-Labor

Diese Notiz ist der Vertrag zwischen den Bausteinen. Wer ein Modul baut, hält sich an die Namen, Datenformen und Aufrufe hier. Wer etwas ändern muss, ändert es hier zuerst.

  → { ok, antworten:[{ok, grund|null, rtt, ttl, von}], trace, text }

6.1 running-config — Anzeige und Wiedereinspielen (verbindlich, 31.10.2026)

Anzeigeform (verbindlich). DHCP-Snooping am Switch (CLI-03, 31.10.2026). running.snooping = {an: bool, vertraut: [Port, …]} ist Teil der laufenden Konfiguration. Die running-config zeigt ip dhcp snooping genau dann, wenn an gilt, und je vertrautem Port ip dhcp snooping trust im interface-Block. Beide Zeilen sind über configure terminal wieder einlesbar; die trust-Zeile ändert ausschließlich vertraut, nie den globalen Schalter. ip dhcp snooping trust ist nur in (config-if) und (config-if-range) zulässig; im globalen Konfigurationsmodus antwortet die Konsole mit Fehler und Hinweis auf den Schnittstellenmodus. no ip dhcp snooping trust entfernt den Port, no ip dhcp snooping schaltet global aus und lässt die Portliste stehen.

show ip dhcp snooping (nur Switch) zeigt „Switch DHCP snooping is enabled|disabled", „DHCP snooping is configured on following VLANs: 1", die Tabelle der vertrauten Ports („Interface"/„Trusted") und die Zeile „DHCP snooping verworfen (seit dem letzten Neustart)" je Port. Bei ausgeschaltetem Snooping nennt die Ausgabe den Befehl zum Einschalten. Ehrliche Grenze: Das Modell bildet Snooping nur über das Port-Vertrauen ab, nicht über eine VLAN-Zuordnung; echte Cisco-Hardware wurde nicht geprüft. Die Roundtrip-Invariante aus § 6.1 gilt unverändert.

10.3 Verhalten (Simulation)

  1. Ablauf in virtueller Zeit. Ist L.t > l.bis, gilt die Lease als abgelaufen: Sim.adresse liefert quelle:"keine", der nächste Zugriff holt neu. Kein neuer Timer, kein neues Ereignis — Ablauf wird beim Zugriff festgestellt.
  2. Erneuerung bei 50 %. Gültige Lease und L.t >= t1: Renew (Unicast Request/Ack); sonst Discover.
  3. Reservierung. Passt die Client-MAC, wird diese IP angeboten (auch außerhalb start..anzahl), aber nur wenn frei; sonst kein Angebot, Grund DHCP_RESERVED_BUSY.
  4. Optionen. Der Ack trägt domain (Option 15); leaseS kommt aus dem Pool.
  5. Adresskonflikt. Vor dem Angebot prüft der Server gegen Geräte und fremde Leases; doppelt belegt → nächste Adresse, Konflikt wird vermerkt (leases[ip].konflikt mit Zeitpunkt). show ip dhcp conflict gibt echte Zeilen aus.
  6. Rogue-DHCP. Ein zweiter Server im LAN ist erlaubt; der Client nimmt das erste Angebot und kann falsches Gateway/DNS erhalten. Grund DHCP_ROGUE_OFFER (Schicht 7).
  7. DHCP-Snooping. Bei snooping.an werden Server-Nachrichten (UDP 67 → 68) von nicht vertrauten Ports verworfen; Zähler steigt, Client bekommt kein Angebot. Grund DHCP_SNOOPING_BLOCKED (Schicht 2). Client-Nachrichten (68 → 67) sind immer erlaubt.

10.4 Neue Gründe (Codes) — genau diese fünf, keine weiteren

CodeSchichtAusgelöst wenn
DHCP_LEASE_EXPIRED7Lease abgelaufen und in diesem Lauf kein neues Angebot
DHCP_RESERVED_BUSY7Reservierung zeigt auf eine nicht freie Adresse — der Server gibt kein Angebot
DHCP_ROGUE_OFFER7Client nimmt ein Angebot eines unerwarteten Servers
DHCP_SNOOPING_BLOCKED2Server-Antwort an einem nicht vertrauten Switch-Port
DHCP_CONFLICT7Eine Adresse liegt auf mehr als einem Gerät; der Server überspringt sie und nennt diesen Grund

Vorrang, wenn mehrere zutreffen: DHCP_RESERVED_BUSY → DHCP_CONFLICT → DHCP_POOL_EMPTY → DHCP_LEASE_EXPIRED → DHCP_NO_OFFER. Der Client wiederholt den Discover bis zu 3×; ein Server-Grund steht einmal je Versuch in der Trace, das Ergebnis grund des Aufrufs ist genau einer. 12.5 Hilfecode H-XXXX-XX

Der Azubi kann der Lehrkraft sagen, wo er hängt, ohne Server, Konto oder Bewertung.
