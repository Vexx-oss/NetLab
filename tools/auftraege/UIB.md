UMFANG
1. Inspektor mit Reitern je Gerätetyp: Übersicht (Name, Strom, Portliste mit Status/Gegenstelle, Neustart, bei IOS-Geräten Hinweis „running ≠ startup“ mit Knopf „Speichern (copy run start)“) · Schnittstellen (Host: DHCP an/aus, IP, Maske (auch „/24“ eingebbar → umrechnen), Gateway, DNS; „Adresse erneuern“ → Sim.dhcp, falls vorhanden; Router: je Schnittstelle IP/Maske/shutdown/Beschreibung/NAT-Rolle/ACL in/out/helper, Subinterfaces anlegen/löschen mit VLAN und nativ; Switch: Portliste kompakt mit Modus access/trunk, Access-VLAN, erlaubte VLANs, Native VLAN, shutdown, Port-Security; SVI) · VLAN (Switch: VLAN-Datenbank anlegen/umbenennen/löschen mit Hinweis „liegt in flash:vlan.dat – überlebt write erase“) · Routing (Router/Firewall: statische Routen, Default-Route, Vorschau der Routingtabelle inkl. verbundener Netze) · Dienste (Server/Host: HTTP/HTTPS/DNS-Einträge/DHCP-Pools/Datei/SSH/Druck an/aus; Router: DHCP-Pools und ausgeschlossene Bereiche, ACL-Editor (Regeln hinzufügen/verschieben/löschen, Reihenfolge sichtbar nummeriert, implizites „deny any“ als graue letzte Zeile, Zuweisung an Schnittstellen in/out), NAT (statisch, PAT); Firewall: Zonen je Schnittstelle, Regeltabelle mit Verschieben/aktiv, Quell-NAT, Port-Weiterleitung) · Konsole (UI.konsole bzw. Terminal für Hosts).
   - Live-Prüfung beim Tippen (Modell.pruefen + eigene Feldprüfung mit IP.*): Feld rot/gelb mit erklärendem Satz darunter, sofort, nicht erst beim Speichern. Übernehmen bei Enter/Verlassen des Feldes; jede Änderung = ein Rückgängig-Schritt.
   - Unter jeder Änderung die Zeile „entspricht: <code>…</code>“ (CLI.entspricht(geraet, pfad, wert), falls vorhanden, sonst ausblenden) mit Knopf „In Konsole übernehmen“ (öffnet den Konsole-Reiter und setzt den Befehlsblock als Vorschlag in die Eingabe). So lernt man die CLI nebenbei.
   - Internet-Gerät: nur Anzeige (Kulisse), erklärender Text.
2. Konsole (UI.konsole): Terminal-Optik (--mono), Ausgabe scrollt, Prompt aus CLI.prompt(sitzung), Eingabezeile mit Verlauf (↑/↓), Tab → CLI.tab (Vorschläge anzeigen), ? sofort (ohne Enter) wie IOS (CLI.eingabe(sitzung, zeile + "?")), Strg+C/Strg+Z (→ end), mehrzeiliges Einfügen, Klick in die Ausgabe fokussiert die Eingabe. Im Einstieg-Niveau (store.get("einst",{}).niveau === "E" oder nicht gesetzt): kleine Zeile „Vorschlag: <befehl>“ (CLI.vorschlag) zum Anklicken. Sitzung je Gerät im Speicher halten (Map geraetId → Sitzung), solange das Netz dasselbe ist. Rückfragen (copy run start, reload) funktionieren als Dialog in der Konsole. Übergib CLI.sitzung(netz, id, {verlauf, einstieg}).
3. Simulations-Panel (UI.simpanel): Ereignisliste (eine Zeile je Etappe: Nr., Zeit, Gerät, Art-Symbol, Protokoll-Chip in Protokollfarbe MIT Text, Klartext), Filter nach Protokoll, Klick auf Zeile → Gerät leuchtet (UI.labor.hervorheben) und PDU-Inspektor zeigt den Frame; Steuerung Play/Pause, Schritt vor/zurück, Tempo (0,5×/1×/2×/4×), an den Anfang; Umschalter „Ergebnis“ (nur Zusammenfassung) vs. „Schritt für Schritt“ wie Packet Tracer; Wiedergabe ruft UI.labor.animiere(ereignis) für „senden“-Ereignisse. Verworfene Ereignisse rot mit Grundcode; Erklärung abhängig vom Niveau: DATEN.lehrtexte[code]?.[niveau] (niveau = store.get("einst",{}).niveau || "E"; Werte "E"|"AP1"|"AP2"), Fallback Sim.GRUENDE?.[code]?.titel bzw. der Code. Timeout (still verworfen) vs. Destination unreachable (gemeldet) sichtbar unterschieden. Oben eine Zusammenfassung (trace.zusammenfassung) mit großem ✓/✗.
4. PDU-Inspektor (UI.pdu): aufklappbare OSI-Schichten (L2 Ethernet inkl. 802.1Q-Tag, ARP, L3 IPv4, L4 ICMP/TCP/UDP, L7 DHCP/DNS/HTTP), Felder mit Werten (MAC im Cisco- oder Doppelpunkt-Format), GEÄNDERTE Felder gegenüber dem vorigen Ereignis desselben Pakets hervorgehoben (MAC wechselt am Router, IP nicht, TTL −1) mit kurzer Erklärung „warum geändert“; je Schicht ein Satz Erklärung (für Einsteiger).
5. Zugänglichkeit: Tastatur bedienbar, Farben immer mit Text/Symbol, Hell/Dunkel über Tokens, ruhige, klare Gestaltung im Leitstand-Stil.
